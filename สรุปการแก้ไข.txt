สรุปการแก้ไขระบบ ART Maintenance
โฟลเดอร์: ART-Maintenance-UI-Old-New
อัปเดต: 27 พ.ย. 2026

แก้ 3 ด้าน
  1) ลดการใช้เน็ตและฐานข้อมูล (สาเหตุที่ Neon กิน traffic สูง)
  2) แก้บั๊กที่ใช้งานไม่ได้หรือแสดงผลผิด
  3) จัดโค้ดให้ดูแลง่ายขึ้น (refactor) - ย้ายครบทุกหน้าแล้ว


==================================================
1) ลดการใช้เน็ตและฐานข้อมูล
==================================================

1.1 หน้าเว็บดึงข้อมูลทั้งหมดซ้ำทุกไม่กี่วินาที
    ปัญหา : ดึงงานทั้งหมดพร้อมรูปซ้ำทุกรอบ แม้ไม่มีอะไรเปลี่ยน
    แก้   : ฐานข้อมูลมีเลขเวอร์ชันข้อมูล (ตาราง app_state + trigger)
            ถ้าเลขไม่เปลี่ยน /api/data?since= จะตอบแค่ {unchanged:true}
    ผล   : เปิดหน้าทิ้งไว้ 2 นาที 1.06 MB -> 0.01 MB

1.2 Backup เต็มทุกครั้งที่เซิร์ฟเวอร์รีสตาร์ท
    ปัญหา : ทุกครั้งที่ Render รีสตาร์ท จะดึงข้อมูลและรูปทั้งหมดออกมา backup
    แก้   : backup วันละครั้ง (จำเวลาล่าสุดไว้ในฐานข้อมูล)
            ตั้งค่าได้ด้วย AUTO_BACKUP = full / no-images / off
    ผล   : รีสตาร์ท 138 MB -> 0.01 MB
    หมายเหตุ: ค่าเริ่มต้นคือ full ครั้งแรกของแต่ละวันจึงยังดึงข้อมูลทั้งหมดอยู่
            บน Render แนะนำให้ตั้ง AUTO_BACKUP=no-images หรือ off
            (รายละเอียดใน OPERATIONS.md)

1.3 สร้างงานใหม่ดึงข้อมูลทั้งแผนก
    ปัญหา : หาเลขงานถัดไปด้วยการดึงทุกงานในแผนกพร้อมรูป
    แก้   : ให้ฐานข้อมูลส่งกลับมาเฉพาะเลขงานกับวันที่สร้าง
    ผล   : สร้างงาน 1 งาน 139 MB -> 0.94 MB

1.4 กดบันทึกแล้วส่งรูปซ้ำทุกครั้ง
    แก้   : ไม่ส่งรูปตอนบันทึก (PUT) รูปเดิมฐานข้อมูลเก็บไว้ให้เอง

1.5 ประวัติการทำงาน (audit log) ถูกส่งทั้งหมดทุกครั้ง
    แก้   : ส่งเฉพาะรายการใหม่ที่ยังไม่ได้บันทึก

1.6 ข้อมูลส่งไปเบราว์เซอร์แบบไม่บีบอัด
    แก้   : บีบอัดด้วย gzip

1.7 รูปถูกโหลดใหม่ทุกครั้ง
    แก้   : ให้เบราว์เซอร์เก็บรูปไว้ใช้ซ้ำ 1 วัน

ผลรวม (ทดสอบกับข้อมูลจำลอง 120 งาน รูปรวม 137 MB)
                                    ฐานข้อมูล->เซิร์ฟเวอร์     เซิร์ฟเวอร์->เบราว์เซอร์
  เซิร์ฟเวอร์รีสตาร์ท                138 MB  -> 0.01 MB          -
  เปิดหน้า 6 รายการแล้วกลับ           4.2 MB  -> 0.01 MB          4.2 MB  -> 0 MB
  เปิดหน้าทิ้งไว้ 2 นาที              1.06 MB -> 0.01 MB          1.04 MB -> 0 MB
  สร้างงานใหม่ (แนบรูป 3 รูป)         139 MB  -> 0.94 MB          - -> 0.24 MB
  ------------------------------------------------------------------------------
  รวมทั้งชุด                          289 MB  -> 2.68 MB (ลด ~99%)  11.3 MB -> 1.26 MB (ลด ~89%)

ขนาดไฟล์หน้าเว็บ (หลังบีบอัด gzip): JS 94 KB, CSS 26 KB


==================================================
2) บั๊กการใช้งาน
==================================================

2.1 ผู้อนุมัติที่ไม่ใช่แอดมินกดอนุมัติไม่ได้ (ขึ้นว่าไม่มีสิทธิ์)
    สาเหตุ: ระบบเทียบข้อมูลก่อนและหลังอนุมัติแบบสนใจลำดับ key
    แก้   : เทียบแบบไม่สนลำดับ key (stableJson)

2.2 ช่างรับงานไม่ได้ (ขึ้นว่าไม่มีสิทธิ์)
    สาเหตุ: หน่วยงานซ่อมของช่างเก็บด้วยตัวพิมพ์ใหญ่หรือเล็กไม่ตรงกับในระบบ
    แก้   : แปลงเป็นรหัสมาตรฐานโดยไม่สนตัวพิมพ์

2.3 หลายหน้าแสดงชื่อและเวลาไม่ตรงกับงานจริง
    ได้แก่ ผู้รับผิดชอบ, ผู้อนุมัติ, ผู้เสนอเวลา, เวลาเริ่ม/จบ/ระยะเวลาซ่อม และไทม์ไลน์
    แก้   : ดึงจากข้อมูลงานจริงทุกจุด

2.4 หน้าแจ้งเตือนแสดงวันที่ดิบ เช่น 2026-11-25T15:40
    แก้   : แสดงเป็นวันที่ภาษาไทย

2.5 การ์ดสถานะ 7 ใบ กดด้วยคีย์บอร์ดได้แค่ใบเดียว
    แก้   : กดได้ครบ 7 ใบ (Enter หรือ Space)

2.6 หน้าล็อกอินบนคอมถูกบีบเป็นคอลัมน์แคบ 640px
    สาเหตุ: กฎ CSS ส่วนกลางที่เขียนทีหลังทับเลย์เอาต์เต็มจอของหน้าล็อกอิน
    แก้   : เพิ่มบล็อกท้าย src/App.css ให้หน้าล็อกอินใช้ค่าที่ออกแบบไว้
            (ไม่กระทบหน้าอื่น ถ้าไม่ต้องการ ลบบล็อกที่ขึ้นต้นด้วย
             "Login page: restore the full-screen layout" ได้เลย)

2.7 npm run dev:local รันครั้งที่สองแล้วพัง
    แก้   : ไม่สร้างฐานข้อมูลทดสอบซ้ำถ้ามีอยู่แล้ว


==================================================
3) จัดโค้ด (refactor)
==================================================

App.tsx เดิมเป็นไฟล์เดียวยาว 4,261 บรรทัด ตอนนี้เหลือ 1,489 บรรทัด
(เหลือแค่ state, การโหลด/บันทึกข้อมูล และตัวสลับหน้า)

3.1 ส่วนที่ใช้ร่วมกัน
  src/api/client.ts                   การเรียก API
  src/lib/repairs.ts                  ค่าคงที่และฟังก์ชันเกี่ยวกับงานซ่อม
  src/lib/images.ts                   ย่อขนาดรูปก่อนอัปโหลด
  src/lib/format.ts                   แสดงวันที่ภาษาไทย
  src/components/StatusCard.tsx       การ์ดสถานะ
  src/components/ImageLightbox.tsx    ตัวดูรูปเต็มจอ
  src/components/LoginGearGraphic.tsx กราฟิกหน้าล็อกอิน

3.2 ย้ายครบทุกหน้า: 30 หน้าอยู่ใน src/pages/ หน้าละ 1 ไฟล์
  ล็อกอิน/เมนู      LoginPage, DivisionPage, DepartmentPage, DepartmentHomePage,
                    ChangePasswordPage, NotificationsPage
  แจ้งซ่อม/รายการ    NewRepairPage, RepairsPage, RepairDetailPage, RepairPdfPage,
                    CompletedListPage, RepairingListPage
  อนุมัติ            ApprovalListPage, ApprovalRejectedListPage, RejectedListPage
  รับงาน/เวลาซ่อม    RepairAssignmentListPage, RepairAssignmentPage,
                    RepairTimeListPage, RepairTimePage, RepairTimeReviewPage
  ซ่อม/ตรวจงาน      RepairExecutionPage, InspectionListPage, InspectionPage
  สถานะแผนก         DepartmentControlHistoryPage
  ผู้ดูแลระบบ        UserManagementPage, AddUserPage, UserHistoryPage,
                    SystemRecoveryPage, OrganizationManagementPage, OrganizationAddPage

  src/pages/pageContext.ts  รายการ state และฟังก์ชันที่ App ส่งให้หน้าต่างๆ (196 รายการ)
                            แต่ละหน้าระบุชัดเจนว่าใช้ตัวไหนบ้าง (Pick<...>)

วิธีย้าย: ใช้สคริปต์ย้าย JSX ของแต่ละหน้าออกมาตามเดิมทุกตัวอักษร
ไม่ได้แก้ข้อความ, class, ลำดับ หรือ logic ใดๆ
App ยังเป็นตัวตัดสินว่าจะแสดงหน้าไหน (เงื่อนไขเดิม รวมทั้งเช็ค isAdmin)

ผู้ใช้ไม่เห็นความต่าง แต่ทีมเปิดแก้ทีละหน้าได้ เห็นชัดว่าแต่ละหน้าใช้ข้อมูลอะไร
และเสี่ยงไปพังหน้าอื่นน้อยลง

ขั้นต่อไปที่แนะนำ (ยังไม่ได้ทำ):
  - แยก state ของแต่ละกลุ่มงานออกเป็น hook/context
    เพื่อลดรายการ 196 ตัวใน pageContext
  - จัดย่อหน้า (format) โค้ดในไฟล์หน้า ตอนนี้ย่อหน้ายังไม่สม่ำเสมอเหมือนต้นฉบับ
    แนะนำใช้ prettier ทีเดียวทั้งโปรเจกต์
  - RejectedListPage ไม่มีปุ่มไหนพาไปหน้านี้ (มีมาตั้งแต่โค้ดเดิม)
    ควรถามทีมว่ายังใช้อยู่ไหม

ทดสอบทั้งหมดกับฐานข้อมูลจำลองในเครื่อง ไม่ได้แตะฐานข้อมูลจริง

==================================================
ขั้นตอนนำไปใช้
==================================================

  1. npm ci
  2. npm run build
  3. ตั้ง AUTO_BACKUP=no-images (หรือ off) บน Render
  4. deploy ขึ้น Render หรือ GitHub Pages ตามปกติ

  หมายเหตุความปลอดภัย: รหัสผ่านฐานข้อมูล Neon เคยถูกส่งต่อในแชต
  ควรเปลี่ยนรหัสผ่านใหม่ และอัปเดต DATABASE_URL บน Render
